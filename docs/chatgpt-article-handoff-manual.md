# 商品比較記事の担当者間引き継ぎ手順書

## 目的

ChatGPTチャットモードで集めた調査結果を、別の担当者が同じ基準で記事に仕上げ、確認後に公開できるようにする。担当者は「調査担当」と「記事化担当」に分かれてよい。1人で両方を担当しても手順は省略しない。

## 役割

### 調査担当

- [ChatGPT依頼テンプレート](./chatgpt-article-research-prompt.md)を使う
- 商品A/Bの選定、公式情報、商品画像、SNS/口コミ、楽天・Amazonの販売URLを調査する
- 見つからない情報を推測で補わない
- ChatGPTの返答を改変せず保存する

### 記事化担当

- 受け取った返答ファイルだけを入力にする
- URL、型番、画像、SNS投稿を個別に確認する
- 確認できた情報だけを記事へ反映する
- 未確認項目を残したまま公開しない

### 公開担当

- ローカル表示と検証コマンドの結果を確認する
- 明示的な公開指示が出た場合だけデプロイする
- デプロイ後に本番URLを確認し、完了を報告する

## 手順

### 1. 調査を依頼する

> **使用するモード：ChatGPTのチャットモードのみ。Workモード、Codexの作業スレッド、エージェント実行へ依頼しない。**

1. `docs/chatgpt-article-research-prompt.md`を開く。
2. `{{カテゴリ}}`、`{{用途}}`、`{{AmazonストアID}}`を置き換える。
3. 商品候補が決まっている場合は、比較テーマ欄に正式名称または型番を入れる。
4. 依頼文をChatGPTのチャットモードへ貼り付ける。
5. 返答が最後の出力フォーマットまで揃うのを待つ。

ChatGPTチャットモードの返答は自動的にCodexへ渡らない場合がある。返答全文をコピーし、必ず次の受け渡し手順へ進む。

### 2. 調査結果を受け渡す

1. ChatGPTの返答を編集せずコピーする。
2. `research/inbox/YYYY-MM-DD-<slug>.md`として保存する。
3. ファイル先頭に次の状態行を追加する。

```text
status: research-received
researcher: 担当者名
received_at_jst: YYYY-MM-DD HH:mm
```

4. 記事化担当へ、ファイルパスと対象slugだけを伝える。
5. 「調査済み」「記事化済み」「公開済み」を混同しない。返答を受け取っただけでは記事完成ではない。

### 3. 記事化担当が検証する

1. 返答ファイルの商品A/B、型番、公式URLを確認する。
2. 公式ページで商品名・型番・比較数値・画像が一致するか確認する。
3. 楽天URLは商品詳細ページであること、商品名・型番・ショップが一致することを確認する。
4. Amazon URLは商品詳細ページまたはASINが一致することを確認し、ストアID付きURLを生成する。
5. SNSは投稿本文または動画タイトルに型番・シリーズがあるか確認し、`model` / `series` / `brand`を判定する。`brand`だけの投稿は埋め込まない。
6. 確認結果を台帳へ転記し、未確認項目は「確認不可」と記録する。
7. seed、購入リンク台帳、画像、SNS埋め込みへ反映する。

### 4. ローカル確認を行う

```powershell
pnpm test
PUBLIC_BUILD_SHA=$(git rev-parse HEAD) pnpm verify
pnpm dev --host 0.0.0.0
```

対象ページで次を目視確認する。

- 商品A/Bの画像が実物と一致している
- 比較表にプレースホルダーがない
- 商品カード内に楽天・Amazonボタンがある
- ボタンのリンク先と商品名・型番が一致している
- SNS投稿が実際の埋め込みとして表示される
- 不要な検索リンク、確認中表示、仮画像、重複カードがない

確認後、返答ファイルの状態を更新する。

```text
status: article-local-verified
verified_by: 担当者名
verified_at_jst: YYYY-MM-DD HH:mm
```

### 5. 公開する

記事化担当は、ローカル確認が終わった時点で止める。公開担当は、ユーザーまたは責任者から明示的に「本番公開」「デプロイ」と指示された場合だけ次を行う。

1. 最新コミットと検証結果を確認する。
2. 本番ビルド・デプロイを実行する。
3. 本番URLで画像、比較表、SNS、楽天・Amazonボタンを確認する。
4. 返答ファイルを次の状態に更新する。

```text
status: production-verified
deployed_by: 担当者名
deployed_at_jst: YYYY-MM-DD HH:mm
production_url: https://...
deployment_id: ...
```

## 受け渡しメッセージの定型

### 調査担当 → 記事化担当

```text
調査結果を受け渡します。
ファイル：research/inbox/YYYY-MM-DD-<slug>.md
対象：商品A vs 商品B
状態：research-received
未確認事項：<あれば記載>
```

### 記事化担当 → 公開担当

```text
記事化とローカル確認が完了しました。
対象：<slug>
状態：article-local-verified
確認結果：画像・比較表・SNS・楽天/Amazon導線を確認済み
残件：<なければ「なし」>
```

## 公開を止める条件

- 商品名または型番が公式ページで確認できない
- 画像が対象商品か確認できない
- 楽天またはAmazonのリンクが別型番・検索結果・不明な短縮URL
- SNS投稿の対象商品が確認できない
- プレースホルダー文や「確認中」が残っている
- ローカル表示を確認していない
- 公開指示がない

## 重要な区別

「ChatGPTへ依頼した」→「返答を受領した」→「記事へ反映した」→「ローカル確認した」→「本番へデプロイした」は別の状態である。報告では必ず状態名とファイルパス、確認日時を併記する。

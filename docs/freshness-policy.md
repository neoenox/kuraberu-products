# 鮮度切れ時の挙動

公開中の記事は、確認日が古くなったときに次のとおり扱う。**自動で非表示にはしない**。検出と通知だけを自動化し、再確認と更新は人（または担当エージェント）が行う。

| 対象         | 確認日の出どころ                                      | 閾値                              | 実行                                                                                   | 鮮度切れ時                                                         |
| ------------ | ----------------------------------------------------- | --------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 価格表示     | 記事の `productInfoCheckedAt`、`src/data/*-prices.ts` | 30日（`DEFAULT_THRESHOLD_DAYS`）  | `price-freshness.yml`（毎週月曜 03:47 UTC）→ `scripts/check-price-freshness.mjs`       | Issue「価格表示の再確認が必要」を作成/更新。全件更新で自動クローズ |
| 仕様クレーム | `data/spec-claims.json` の `checkedAt`                | 180日（`DEFAULT_THRESHOLD_DAYS`） | `spec-claims-freshness.yml`（毎週月曜 03:37 UTC）→ `scripts/spec-claims.mjs freshness` | Issue「仕様表記の再照合が必要」を作成/更新。全件更新で自動クローズ |
| 仕様の乖離   | 公式ページとの指紋                                    | -                                 | `verify:build` 内の `spec-claims.mjs check`                                            | CI失敗                                                             |

## 方針

- 通知のみ: 鮮度切れでも記事・価格は表示し続ける。価格自体の自動取得もしない。
- 通知に失敗した場合は、ワークフローを失敗させる（無言で見逃さない）。
- Issueは1件に集約し、再実行のたびに本文を更新する。
- `src/lib/content-freshness.ts` の `isContentStale`（既定180日）は現状ページ側で使われていない。ページで鮮度切れ表示を出す場合は別Issueで扱う。

## 固定しているもの

`tests/freshness-policy.test.ts` が、この表の閾値とワークフローの通知・自動クローズ動作が実装とずれていないことを検証する。
